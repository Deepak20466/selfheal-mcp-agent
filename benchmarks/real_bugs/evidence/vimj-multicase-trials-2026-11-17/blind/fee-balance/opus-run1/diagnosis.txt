Root cause: in `update_fee` (app/routers/fees.py), the new field values are copied onto the fee, but `balance_amount` is only recalculated when `balance_amount` or `status` is in the request. A request that changes only `amount` or `product_amount` updates the total but leaves the old outstanding balance in place. In the test, the amount goes from 100 to 150 (total 125 → 175), but the balance stays at 125.

Fix: record the old total (`amount + product_amount`) before applying the updates. If the request changes `amount` or `product_amount`, doesn't set `balance_amount` itself, and the fee isn't PAID after the updates, add the change in total to the existing balance, with a floor of 0. Adding the difference, instead of resetting the balance to the full total, keeps any partial payment already made. In the test: 125 + (175 − 125) = 175. Paid fees and explicit `balance_amount` updates work as before, and the existing status-sync logic is unchanged. I haven't run the test.
