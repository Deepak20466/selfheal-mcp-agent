Root cause: update_fee in app/routers/fees.py writes the submitted fields onto the StudentFee row but never recalculates balance_amount. balance_amount is a stored column, so it stays at its original value (100 + 25 = 125) when only `amount` changes to 150, and the response reports 125 instead of 175. The create path sets balance_amount = amount + product_amount, and the outstanding balance should follow the same total when an unpaid fee's amount changes.

Fix: capture the pre-update total (amount + product_amount), apply the updates as before, then for unpaid/overdue fees (status != PAID) that did not explicitly set balance_amount, shift balance_amount by the change in total. Shifting by the delta rather than overwriting with the total keeps any amount already settled against the balance intact. Paid fees, explicit balance_amount updates, and the status-handling branches are untouched, so other behaviour is unchanged. For this test: balance 125 + (150+25 - (100+25)) = 175.
