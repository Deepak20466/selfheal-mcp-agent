Root cause: PasswordResetToken.expires_at is read back from the database as a naive datetime. SQLite's DateTime storage drops tzinfo, and the model column is not declared with timezone=True. reset_password then compares that naive value with datetime.now(timezone.utc), an aware value, which raises "can't compare offset-naive and offset-aware datetimes". The test stores a UTC-aware expiry, and SQLite keeps the UTC wall-clock time, so treating a naive value as UTC is correct. The fix is local to app/routers/auth.py: a small helper attaches UTC to naive datetimes, and reset_password uses it before comparing. The model and the other routes are unchanged. The expired-token case still returns 400 because the normalized expiry is in the past.
