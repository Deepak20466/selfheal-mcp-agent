reset_password compares entry.expires_at with datetime.now(timezone.utc), which is timezone-aware. The token is stored in a DateTime column without timezone=True. SQLite, and some other backends, return naive datetimes for such columns, even though the value was written as aware UTC. The comparison therefore raises "TypeError: can't compare offset-naive and offset-aware datetimes", and the endpoint returns a 500 instead of 200 for a valid token or 400 for an expired one. The fix treats a naive stored expiry as UTC, which is how forgot_password writes it, before comparing.
