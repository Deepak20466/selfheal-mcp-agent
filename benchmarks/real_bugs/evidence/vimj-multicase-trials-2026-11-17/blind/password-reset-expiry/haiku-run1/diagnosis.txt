Root cause: `PasswordResetToken.expires_at` is written as a timezone-aware UTC datetime (`datetime.now(timezone.utc) + timedelta(hours=1)`), but the backing SQLite column is a plain DateTime. SQLite does not store tzinfo, so when the row is read back, `entry.expires_at` is an offset-naive datetime. `reset_password` then compares it with the offset-aware `datetime.now(timezone.utc)`, and Python raises `TypeError: can't compare offset-naive and offset-aware datetimes`. The fix is to normalize the value read from the database to UTC-aware before the comparison. Naive values from the DB hold UTC wall-clock time, because the aware value was written as UTC, so `replace(tzinfo=timezone.utc)` is the correct interpretation. Values that are already aware (e.g. on backends that preserve tzinfo) are left untouched. The change is confined to `reset_password` in app/routers/auth.py and does not alter any other behaviour.
